# Техническое устройство Mesh Atlas

Эта документация описывает поставляемый стенд. Для первого запуска и демонстрации используйте [README](../README.md). Данные учебного эксперимента, результаты расчёта и исходная география имеют разный срок жизни.

## Архитектура

| Компонент | Вход | Ответственность и результат |
|---|---|---|
| server.py | HTTP-запрос с названием или координатами | Раздаёт клиент, вызывает геокодер и Overpass, кэширует геоданные. Для встроенных городов достаточно файлового режима. |
| geodata.py | Элементы OSM с тегами и геометрией | Builder выделяет автомобильные дороги, точки, площадные объекты и ограничения поворота. |
| data/*.js | Снимок города | Регистрирует объект window.cityData. Приложение загружает один выбранный снимок. |
| network.js | Снимок | RoadNetwork строит ориентированный граф, привязывает точки к дорогам и ищет маршрут. |
| simulation.js | Граф, ПВЗ, хаб, параметры, общий спрос | Генерирует поток и проводит отдельный дискретно-событийный прогон для каждой политики. |
| app.js | Действия пользователя | Управляет Web Worker, импортом, сравнением, детализацией заказов и экспортом результата. |
| map.js | Геометрия и события рейсов | Leaflet рисует карту, линии подачи и перевозки, положение машин и карточки узлов. |

Поиск города и выбор стратегии независимы. После загрузки географии маршруты рассчитываются в браузере. Изменение экономического параметра не вызывает сетевой запрос на каждый рейс. Worker получает сообщение init с городом, отвечает ready с привязанными точками. По run выбирает сеть и хаб, генерирует один входной поток, последовательно рассчитывает три политики и возвращает done. История конкретного заказа запрашивается сообщением order. Номер прогона помогает интерфейсу сопоставить ответ с текущим экспериментом.

## Установка и эксплуатация

Для полного режима нужны современный браузер с Web Worker, Python 3.9+ и доступ в интернет для новых городов. Зависимости сервера входят в стандартную библиотеку. Leaflet поставляется локально. Для автоматической проверки движка подходит Node.js 20+. Из корня репозитория:

~~~sh
python server.py 8080 --no-browser
~~~

Откройте http://127.0.0.1:8080/. Без аргументов сервер выбирает свободный порт и открывает браузер. На Windows аналогичный запуск выполняет Start.cmd. Для демонстрации без интернета откройте index.html и выберите встроенный город. Для остановки процесса в терминале используйте Ctrl+C.

Сервер привязан к loopback. Многопользовательская авторизация, серверная очередь экспериментов и постоянное хранилище заказов в этой версии отсутствуют. Перезагрузка вкладки сбрасывает эксперимент. Чтобы воспроизвести его позднее, сохраните экспорт и тот же снимок географии.

## HTTP API

| Метод и путь | Параметры запроса | Успешный ответ |
|---|---|---|
| GET /api/search | q — название от двух символов | Массив объектов name, lat, lon. Если геокодер вернул границы, bounds содержит south,west,north,east. |
| GET /api/city | name, lat, lon, km. Опциональный bounds в том же порядке | JSON-снимок с ключами name, center, bbox, vertices, roads, areas, points, turns, date. |

Пример запроса области: GET /api/city?name=Kazan&lat=55.79&lon=49.12&km=3. Параметр km задаёт полуширину области вокруг центра, допустимый диапазон 1–30 км. При передаче bounds используются заданные границы. Пустой результат поиска — пустой массив. Обработанная ошибка API возвращает HTTP 503 с полем error. Перед разбором снимка клиенту следует проверить HTTP-статус.

Поиск сначала обращается к Nominatim, затем при необходимости к Photon. Загрузка карты перебирает публичные серверы Overpass. Ключ дискового кэша — SHA-256 от параметров запроса, каталог mesh-atlas-osm-v3 в системной временной папке. Запись происходит через временный файл и атомарное переименование. Результаты используются до семи суток. Для крупного города при тайм-ауте выберите меньшую область.

## Геоданные и маршруты

Внутри снимка координаты хранятся как [широта, долгота]. Массив vertices индексируется с нуля. Каждая запись roads содержит [OSM way ID, имя, класс дороги, скорость км/ч, направление, индексы вершин]. Направление 1 означает движение по перечислению, −1 — обратное, 0 — двустороннее. Запись turns связывает вершину, входящий way, исходящий way и тип ограничения. Во внешнем GeoJSON порядок координат обратный: [долгота, широта].

При инициализации движок находит крупнейшую сильно связную компоненту. В пределах 700 м точка привязывается к ближайшей подходящей вершине. Для поиска пути A* использует длину либо оценку времени. При проверке ограничений учитываются входящий участок и предыдущая вершина. Ключ кэша маршрута включает начало, конец, закрытый участок и метрику. Недостижимый путь представляется null. Геометрия рейса — последовательность вершин найденного пути.

Режим перекрытия отключает один OSM way. Длинная улица может состоять из нескольких way. Эстакада и дорога под ней связываются только при общем узле графа. Привязка здания к дороге, часы доступа, шлагбаумы, сезонные правила и грузовые ограничения требуют проверки при переносе модели в реальную диспетчерскую.

## Модель дня

Модельное время измеряется в минутах от 08:00, расстояние — в километрах, объём — в литрах, деньги — в рублях. При перегрузке расчёт продолжается за полночь. Фоновый посетитель занимает сотрудника. Отправитель личной посылки дополнительно занимает 2 л на полке до часового вывоза. Оформленные заказы поступают на приёмку, резервируются, собираются и попадают в очередь отправки. Ограничение shelf проверяется при исходной приёмке. Для входящих грузов и возвратов возможна перегрузка точки.

События извлекаются из очереди по модельному времени. Для обслуживания выбирается ближайшее свободное рабочее место. Для перевозки движок ищет свободную машину с доступным путём подачи. Машина занята до конца разгрузки. Группы ограничены числом заказов capacity и объёмом кузова vanLitres. Объём полок и вместимость партии измеряются в разных единицах. После выдачи сценарий возврата создаёт обратное движение и корректирует начисления.

| Политика | Как образуется партия |
|---|---|
| hub | Входящие заказы группируются для доставки на хаб, после сортировки формируются исходящие партии по получателям. |
| direct | Прямые рейсы формируются по парам ПВЗ в десятиминутных окнах. |
| hybrid | Для готовой партии сравниваются прогнозные расходы прямого плеча и двух складских плеч с учётом ожидаемой консолидации. |

### Проверка стоимости рейса

Фактические расходы рейса равны ставке выхода плюс километры подачи и перевозки, умноженные на цену километра, плюс 2 ₽ за каждую минуту от начала подачи до конца разгрузки. Полученное значение делится на фактическое число заказов в машине. Например, при ставке выхода 240 ₽, пробеге 10 км, ставке 24 ₽/км и занятости 40 минут стоимость рейса равна 560 ₽. При восьми заказах транспортная составляющая каждого — 70 ₽.

Ставки пилота хранятся в настройках эксперимента. Прогноз через СЦ включает два консолидированных плеча, выдачу, сортировку (база плюс 0,16 ₽/л) и ожидаемое хранение. Фактическое хранение СЦ считается с момента разгрузки до отправления по 0,001 ₽/л в минуту. Для прямой доставки учитываются транспорт, плата за обработку и полка. Исходящий запас в пилоте занимает полку до получения заказа. Хранение оплачивается за литро-сутки с коэффициентом 1 + заполненность (доля ограничена сверху значением 2). Для сценария залежалого стока учитывается и начальный возраст. Расход полки партнёра задаётся отдельной ставкой. Модель фиксирует начисление при выборе маршрута. На прямом плече резервируется объём у получателя.

Прогноз цены покупателя равен 35% оценённых затрат с округлением до рубля. При согласии на габаритный прямой рейс добавляется доплата. Гибрид сравнивает расходы за вычетом цены и удерживаемой доли доплаты. Таблица заказа отражает фактические срок и деньги в каждом прогоне. Сравнение экономии использует только общие выданные заказы. Выручка покупателя при возврате сторнируется; выплаченная партнёру и грузчикам стоимость уже выполненной работы остаётся расходом.

Посылки формируются из трёх модельных SKU. При городском спросе вероятность точки отправления пропорциональна относительной дальности ближайшего активного соседа, ограниченной диапазоном 0,5–3. В режиме фиксированного числа заказов на точку заказы распределяются поровну. Фоновые посещения в обоих режимах взвешиваются по расстоянию. Это приближение при равной плотности населения и одинаковом штате.



Показатель расходов на исходный заказ делится на весь сформированный спрос. Среднее время до выдачи рассчитывается по выданным заказам. Поэтому стоимость следует читать вместе с числом выданных заказов: отказ при приёмке тоже меняет среднее.

## Импорт, экспорт и воспроизводимость

Готовый [профиль вечернего пика](../peak.json) можно импортировать из раздела «Условия и тарифы». Поддерживается объект параметров или экспорт с полем settings. Для экспорта с именем города выбранный город должен совпадать.

| Группа | Поля и значения |
|---|---|
| Спрос | orders, bulkyShare и consentShare (проценты), seed, profile (day, peak, return, stock), volumeUnit (city или point). В режиме point объём умножается на число фактически выбранных ПВЗ. |
| Точки и транспорт | active, hub, brand, vanLitres, selection (spread, near, cluster, random), vans, capacity. |
| Работа точки | staff, visits, shelf, interval в минутах. |
| Дороги и экономика | metric (time или distance), closed — ID перекрытого way либо 0, traffic — множитель времени, launch, perKm, tariff, premium, storageRate, spaceRate, sortRate. |

Экспорт содержит город, настройки, ID активных точек, дату геометрии, результаты политик и рейсы. Для сравнения алгоритмов фиксируйте снимок, операторов, выбор активных ПВЗ, seed и профиль спроса. Смена версии картографии способна изменить привязку точки и путь даже при прежнем seed. Импорт дополнительных логистических объектов принимает GeoJSON FeatureCollection с геометриями Point и полями role, name, url. Допустимые роли — pickup и hub; address и operator необязательны.

## Проверка и расширение

Выполните из корня:

~~~sh
node check.cjs
~~~

Проверка использует снимок Йошкар-Олы, 3 500 заказов и сценарий с возвратами. Она проверяет воспроизводимость спроса, вместимость машин, отсутствие пересечения рейсов одной машины во времени, принадлежность маршрутов направленным рёбрам, остатки и начисления при возврате. Миниатюрный граф отдельно проверяет одностороннее движение, запрещённый поворот и потерю маршрута после перекрытия.

Для новой стратегии добавьте ключ в STRATEGIES, реализуйте решение о формировании партии в simulation.js и сохраните прежний контракт результата. Подавайте всем политикам один объект спроса. При добавлении вспомогательной функции учтите, что app.js формирует исходник Worker из явно перечисленных функций и классов. Для нового тега источника обновите и классификатор geodata.py, и запрос Overpass в server.py. После изменения сценария проверьте экспорт, повторный импорт, реальный маршрут по графу и сохранение количества заказов.
